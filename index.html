The problem

macOS can’t open BitLocker drives on its own

Plug a BitLocker-encrypted USB drive — including a BitLocker To Go drive created on Windows — into a Mac, and Finder either shows nothing usable or refuses to mount it. macOS has no native BitLocker support, so files that open fine on Windows are simply inaccessible. BitLocker on macOS fixes that: it reads BitLocker and BitLocker To Go volumes on macOS using your password or 48-digit recovery key, no Windows machine required.

How it works

From plugged in to mounted in Finder

The Mac app walks through five steps to unlock a BitLocker USB drive:

  1. Plug in your BitLocker USB drive The app auto-detects BitLocker volumes via macOS DiskArbitration as soon as the drive is connected.
  2. Click Unlock The detected drive appears in the app, ready to unlock.
  3. Enter your password or recovery key Use your BitLocker password, or the 48-digit numerical recovery key.
  4. Approve the macOS admin prompt Authorize with Touch ID or your Mac password — required for the privileged helper that performs the unlock.
  5. The volume mounts in Finder Browse, copy, and work with your files exactly like any other mounted drive.

Two unlock modes

Decrypted image vs. FUSE-T streaming

BitLocker on macOS supports two ways to get at your files, so you can pick the trade-off that fits your situation.

Path A Default

Writes a fully decrypted image to disk.

  • Portable — works with no extra dependencies
  • Straightforward Finder mount of a full disk image
  • Needs free disk space equal to the drive’s used data
  • Leaves a decrypted image on disk — treat it as sensitive (see Security note below)

Path B Optional

Streams the volume via FUSE-T.

  • Nothing decrypted is written to disk
  • Good when disk space is tight or you only need a few files
  • Uses FUSE-T, a userspace FUSE implementation — no kernel extension
  • Requires installing FUSE-T as an extra dependency

Features

What you get

GUI + CLI

A SwiftUI Mac app for point-and-click unlocking, plus a command-line tool for scripting and headless use.

Auto-detection

BitLocker volumes are found automatically via macOS DiskArbitration as soon as they’re connected.

BitLocker To Go support

Reads the exFAT-personality BitLocker format used on Windows-formatted removable drives.

Password or recovery key

Unlock with your BitLocker password, or the 48-digit numerical recovery key.

Built on dislocker

Both interfaces are backed by the well-tested dislocker crypto core.

Install

Get started

Today, installing means building from source. You’ll need Homebrew with cmake, pkg-config, and mbedtls@3 (must be v3); Python 3 and Swift ship with macOS and the Xcode Command Line Tools. FUSE-T is optional, only needed for Path B streaming. 

git clone --recurse-submodules https://github.com/Adam-Dangerfield/bitlocker-unlock-macos.git

Full build steps, dependency install commands, and troubleshooting live in the project README.

FAQ

Frequently asked questions

Can macOS read BitLocker drives?

Not natively. macOS has no built-in support for reading BitLocker-encrypted volumes. BitLocker on macOS adds that support with a free, open-source Mac app and command-line tool.

Is this free?

Yes. It’s free and open source under the GPLv2 license. Today you build it from source; the project is unsigned, so on first launch you’ll need to right-click the app and choose Open to bypass Gatekeeper.

Does it support BitLocker To Go?

Yes. BitLocker To Go (the exFAT-personality BitLocker format used on removable USB drives) is supported, unlocking with either your password or the 48-digit recovery key.

Do I need a kernel extension?

No. The default mode (Path A) writes a decrypted image to disk and needs no kernel extension. The optional streaming mode (Path B) uses FUSE-T, a userspace FUSE implementation, so no kernel extension is required either way.

Security note

Honest about the trade-offs

Single-user threat model

  • This tool is designed for a single-user Mac, not a shared or multi-user machine.
  • Path A writes a plaintext decrypted image to /private/tmp/bl — treat that path as sensitive while it exists. Path B (FUSE-T streaming) avoids writing on-disk plaintext.
  • A security review has been completed and CRITICAL/HIGH findings have been remediated, with the exception of code signing.
  • The app is intentionally unsigned right now; code signing and notarization are on the roadmap, alongside a native binary rewrite.

Read the full write-up in the repository’s security docs.
